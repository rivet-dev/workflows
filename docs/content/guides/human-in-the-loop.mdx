### What we'll build

- An `approval` workflow per request that records what is being asked and who must answer.
- A Slack message, or an email with links, that shows the request with Approve and Reject buttons.
- A durable wait on the decision queue that can last for days without a running server.
- A timeout path that rejects the request and tells the requester when no one answers.
- The same gate wrapped around an agent's tool call, so the tool runs only after a person approves it.

### Similar tools

This is the same job as Vercel Workflow hooks, Inngest `waitForEvent`, Temporal signals, Cloudflare Workflows `waitForEvent`, or LangGraph interrupts. On Rivet the pending request is an Actor addressed by its key, so the button handler sends the decision straight to it, and the request's state stays readable while it waits.
