This page is not written yet. The outline below is what it will cover.

### What we'll build

- A `/webhooks` route that checks the provider's signature and rejects anything that fails.
- A `customerEvents` workflow per customer, keyed by the customer or object id in the event.
- A record of event ids in the workflow, so a redelivered event is skipped instead of applied twice.
- An acknowledgment sent as soon as the event is queued, well inside the provider's timeout.
- Steps that apply each event to your database in arrival order and retry when your database is down.

### Similar tools

This is the same job as Inngest webhooks, Hookdeck, Svix ingest, Trigger.dev, or a Cloudflare Queues consumer. On Rivet the queue, the ordering, and the record of seen event ids all belong to one Actor per customer, so events for different customers run in parallel while each customer's events run in order.
