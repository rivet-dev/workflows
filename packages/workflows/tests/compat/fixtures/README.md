# Persisted workflow compatibility fixtures

These artifacts were generated by the published legacy
`rivetkit@2.3.7`/`@rivetkit/workflow-engine@2.3.7` pair at Git revision
`b70c717c1a8eef2fe018f803a4ba160547296432`. They use RivetKit's canonical
versioned logical row-dump schema; the generated TypeScript codec in the parent
directory comes from that Rivet-owned schema and is test-only.

The committed artifacts cover three independent actor states:

1. `pending-sleep.vbare` — a pending sleep after a completed state mutation.
2. `pending-message.vbare` — a message wait with a persisted completable row.
3. `replay-retry.vbare` — loop/branch history, retry/error entries, and replay.

Each artifact embeds the legacy package versions, source revision, actor ID,
registry key, schema version, fake-clock seed, and generated-ID seed. The test
runner regenerates the committed bytes with the pinned legacy package, then
executes old-write/new-resume and new-write/old-resume in isolated subprocesses.

The workflow subprocesses restore the canonical logical rows into the workflow
driver, while `rivetkit-core` separately proves that the same fixture model
dumps and restores the real Rivet-owned SQLite tables byte-for-byte. There is no
production or NAPI API for injecting an actor SQLite database, so the current
suite cannot compose those two gates into a single JavaScript actor-host
process. Adding a production database injection API solely for this test would
weaken the storage boundary; an end-to-end host fixture remains deferred until
RivetKit has a test-only actor host that accepts a logical dump.
